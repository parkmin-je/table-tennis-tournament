# 탁구 대회 관리 시스템

안산 지역 탁구 동호회 요청으로 만든 **생활체육 탁구 대회 운영 플랫폼**입니다.
참가 접수 → 조 편성·시드 배정 → 테이블 배정·선수 호출 → 결과 입력 → 본선 진출 → 우승·레이팅 반영까지
대회 하루를 운영진 콘솔 하나로 진행하고, 참가자와 관중은 현황판·대진표로 실시간 확인합니다.

## 기술 스택

| 분류 | 기술 |
|------|------|
| 언어 / 프레임워크 | Java 21, Spring Boot 3.5 (Web, Security, Data JPA, Validation, WebSocket, Actuator) |
| DB | MariaDB 10.6+ (운영) · H2 MariaDB 호환 모드 (로컬·테스트), Flyway 마이그레이션 |
| 화면 | Thymeleaf + Layout Dialect, Bootstrap 5.3, STOMP over WebSocket, FullCalendar — 모두 자체 호스팅(CDN 미사용) |
| 테스트 | JUnit 5, AssertJ, Spring Boot Test, MockMvc, Spring Security Test (H2·MariaDB 양쪽에서 통과) |
| 배포 | Docker 멀티 스테이지 이미지, docker compose (MariaDB 포함), GitHub Actions CI |

## 주요 기능

**대회 운영 (운영진 콘솔 `/manage/tournaments/{id}`)**
- 진행 단계 표시(준비 → 접수 → 마감·체크인 → 예선 → 본선 → 종료)와 단계별 "다음 할 일" 버튼
- 엔트리 관리: 확정/반려, 일괄 확정, 체크인, 입금 확인, 시드·메모, 현장 접수(선수 등록 + 엔트리 한 번에), 기권 처리
- 대진 생성: 토너먼트 / 예선 리그 + 본선, 대진 초기화(경기 시작 전까지)
- 테이블 현황, **빈 테이블 자동 배정** + 선수 호출 알림, 경기 중 선수 중복 배정 차단
- 결과 입력: 게임별 점수(11점·듀스 규칙 검증) / 게임 수 빠른 입력 / 경기 중 기권 / 부전승
- 결과 수정·취소: 승자가 바뀌면 다음 라운드 자리도 자동 교체, 이미 진행된 다음 경기가 있으면 차단
- 심판용 모바일 점수 입력 화면, 참가자 명단·경기 결과 CSV(엑셀) 내보내기

**대진 엔진 (`bracket` 패키지 — 스프링 의존 없는 순수 로직 + 단위 테스트)**
- 표준 시드 배치(1·2번 시드는 결승에서만 만남), BYE는 항상 상위 시드에게 → BYE끼리 붙는 경기 없음
- 결승까지 전체 트리를 미리 만들고 경기끼리 연결 → 승자는 항상 정해진 자리로 진출
- 조 편성: 시드 순 스네이크 + 같은 클럽 분산, 조 인원 차이 최대 1명
- 리그 경기 순서: 서클 방식(같은 선수 연속 경기 방지)
- 조별 순위: ITTF 방식(승점 → 동률자 간 승점 → 게임 득실률 → 점수 득실률 → 시드)
- 본선 진출자 배치: 조 1위 상위 시드, 같은 조 출신은 최대한 늦게 만나도록 배치
- Elo 레이팅: 대회 종료 시 단식 경기로 갱신(부전승·BYE 제외), 결승 결과 수정 시 되돌린 뒤 재계산

**참가자·관중**
- 대회 목록·상세(개요/참가자/예선 리그/본선 대진/레이팅 변동), 실시간 테이블 현황·다음 경기·최근 결과
- **체육관 대형 화면용 현황판** (`/tournament/{id}/board`, 다크 테마·전체 화면·시계)
- 인쇄용 대진표, 대회 일정 캘린더, 선수 랭킹·전적·레이팅 이력, 클럽, 게시판(공지/자유/후기), 알림
- 참가 신청: 선수 프로필(성별·부수·클럽) 기반 자격 검사(부수 범위·성별·정원·마감), 복식 파트너 지정

## 보안·운영 설계

- **권한 3단계**: 회원(USER) / 운영진(STAFF: 대회 진행) / 관리자(ADMIN: 대회 생성·회원 관리). 권한 변경·비활성화 시 해당 세션 즉시 만료
- **동시성**: 같은 대회의 상태를 바꾸는 작업은 대회 행 비관적 락으로 직렬화(운영진 여러 명·서버 여러 대에서도 안전), 엔티티 낙관적 락(@Version), DB 유니크 제약
- **실시간 갱신**: 트랜잭션 커밋 후에만 "변경됨" 신호를 보내고, 화면은 서버 렌더링 조각을 다시 받아 교체(클라이언트 HTML 조립 없음 → XSS 원천 차단). 연결이 끊기면 30초 폴링으로 대체
- **XSS/CSP**: 모든 출력은 이스케이프, 인라인 스크립트 0개, `script-src 'self'` CSP
- **로그인 보호**: IP·아이디 각각 실패 횟수 제한, 인증 전에 잠금 확인. 클라이언트 IP는 신뢰한 프록시 설정으로만 판단
- **IDOR 차단**: 댓글·게시글·알림·참가 신청은 본인 또는 운영진만 변경
- **오류 처리**: 업무 규칙 위반은 이전 화면에 메시지로 표시, 내부 오류는 상세 정보 없이 기록
- **기본 계정 없음**: 운영 환경 관리자 계정은 `ADMIN_PASSWORD` 환경변수로 최초 1회 생성(코드·로그에 비밀번호 없음)
- **스키마 관리**: Flyway 버전 마이그레이션 + `ddl-auto=validate`

## 실행 방법

### 로컬 개발 (DB 설치 없이)

```bash
./gradlew bootRun
```

`local` 프로필이 H2 파일 DB(`./data`)로 기동하고 **샘플 데이터**(진행 중 대회·종료 대회·접수 중 대회)를 만듭니다.

| 계정 | 비밀번호 | 권한 |
|------|----------|------|
| admin | admin1234! | 관리자 |
| staff | staff1234! | 운영진 |
| user1 ~ user8 | user1234! | 회원 |

접속: http://localhost:8080 · 데이터 초기화는 `data` 폴더를 지우고 다시 실행

### 운영 배포 (Docker)

```bash
cp .env.example .env      # DB_PASS, DB_ROOT_PASS, ADMIN_PASSWORD 등을 채운다
docker compose up -d
```

- 앱은 `127.0.0.1:8080`에만 열립니다. 앞단의 Nginx/Caddy가 HTTPS를 처리하고 `X-Forwarded-*` 헤더를 붙여 전달하도록 설정하세요(WebSocket `Upgrade` 헤더 전달 포함)
- 헬스 체크: `/actuator/health`
- DB 백업 예: `docker compose exec db mariadb-dump -upingpong -p pingpong > backup.sql`

### 직접 실행 (jar)

```bash
./gradlew bootJar
SPRING_PROFILES_ACTIVE=prod DB_URL=jdbc:mariadb://host:3306/pingpong DB_USER=... DB_PASS=... \
ADMIN_PASSWORD=... java -jar build/libs/pingpong.jar
```

## 대회 당일 운영 순서

1. **관리자** `대회 만들기` → 방식(토너먼트 / 예선 리그 + 본선), 게임 수, 조 인원, 진출 인원, 테이블 수, 부수·성별 제한, 체크인 필수 여부 설정
2. 운영 콘솔에서 `접수 시작` → 회원이 직접 신청하거나 운영진이 대리 등록 → `신청 일괄 확정`
3. `접수 마감` → 당일 접수처에서 **체크인**·입금 확인, 현장 접수자는 `현장 접수`로 추가, 필요하면 시드 지정
4. `대진 생성` → 참가자에게 대진 발표 알림, 체육관 TV에 **현황판** 띄우기
5. `빈 테이블 자동 배정`(선수에게 호출 알림) → 경기가 끝나면 테이블 카드의 `결과 입력`
6. 예선 리그가 모두 끝나면 `본선 대진 생성` → 같은 방식으로 진행
7. 결승 결과를 입력하면 대회가 자동 종료되고 우승자 알림·레이팅이 반영됩니다. CSV로 결과 보관

불참·부상: 엔트리 `기권` 처리 시 남은 경기는 모두 상대 부전승으로 자동 처리됩니다.

## 프로젝트 구조

```
src/main/java/com/parkminje/pingpong/
├── bracket/       # 대진 엔진 (시드 배치, 조 편성, 리그 일정, 순위, 점수 규칙, Elo) — 순수 자바
├── tournament/    # 대회 (설정, 상태 전환, 공개 화면)
├── entry/         # 참가 엔트리 (신청, 자격 검사, 체크인, 기권)
├── match/         # 경기 (대진 생성, 진행, 진출 규칙, 순위표)
├── live/          # 화면 읽기 모델, 커밋 후 실시간 신호
├── operation/     # 운영 콘솔, 현장 접수, CSV 내보내기
├── player/ club/  # 선수·클럽·레이팅
├── board/ notification/ user/ admin/ home/
├── security/      # 로그인 보호, 세션 관리
├── config/        # 보안, WebSocket, 웹 설정
└── bootstrap/     # 최초 관리자 생성, 로컬 샘플 데이터
src/main/resources/db/migration/   # Flyway 스키마
```

## 테스트

```bash
./gradlew test
```

- `bracket/*Test` — 대진 엔진 단위 테스트 (2~100명 BYE 배치, 조 편성, 리그 일정, ITTF 순위, 점수 규칙, Elo)
- `TournamentFlowTest` — 토너먼트·리그 전체 진행, 결과 수정 전파, 결승 수정 시 레이팅 재계산, 기권, 테이블 충돌, 대진 초기화, 체크인
- `EntryRulesTest` — 부수·성별·정원·중복·복식 파트너·취소 후 재신청 규칙
- `WebPagesTest` — 전 화면 렌더링(비로그인·회원·운영진·관리자), XSS 이스케이프, CSP, 권한 차단, CSRF, 댓글 IDOR

## 알려진 제한

- 한 대회 = 한 종목(예: "남자 3~5부 단식")입니다. 부수별로 여러 종목을 운영하면 종목마다 대회를 만듭니다.
- 단체전은 지원하지 않습니다. 복식 경기는 레이팅에 반영하지 않습니다.
- 로그인 실패 횟수 기록과 WebSocket 브로커는 서버 메모리에 있습니다. 서버를 여러 대로 늘리면 Redis와 외부 STOMP 브로커가 필요합니다. 경기 데이터의 정합성은 DB 락으로 보장됩니다.
